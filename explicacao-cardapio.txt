EXPLICACAO DO APLICATIVO CARDAPIO

OBJETIVO DO APP
O aplicativo mostra um cardapio de restaurante. Quando abre com internet, ele inicia um servidor mock HTTP dentro do proprio app e busca os dados por requisicao HTTP. Esse mock entrega um JSON com id, nome, preco e url da imagem. As imagens ficam em assets e tambem sao obtidas por HTTP pelo servidor mock. Se a carga online funcionar, o app salva os dados no SQLite e salva as imagens no sistema de arquivos. Se o app estiver offline, ele le os dados locais e mostra o preco como "a consultar".

ARQUIVOS PRINCIPAIS
MainActivity.kt: controla a tela, busca o JSON, baixa imagens, chama o SQLite e monta os cards visuais.
CardapioDBHelper.kt: cria e manipula o banco SQLite.
MockCardapioServer.kt: cria um servidor HTTP mock dentro do app para entregar o JSON e as imagens.
activity_main.xml: tem o ScrollView e o LinearLayout onde os itens sao adicionados.
AndroidManifest.xml: declara permissao de internet e permissao para verificar estado de rede.
assets/foto1.jpg a assets/foto4.jpg: imagens usadas pelo mock HTTP interno.

FLUXO GERAL
1. A tela abre e executa onCreate.
2. O app pega o LinearLayout do XML e prepara o banco SQLite.
3. O app verifica se existe conexao de internet.
4. Se houver internet, ele inicia o MockCardapioServer.
5. O app chama carregarDadosOnline e acessa o JSON por HTTP em 127.0.0.1.
6. carregarDadosOnline baixa o JSON, percorre os itens, baixa as imagens e salva tudo localmente.
7. Depois mostra os cards com nome, foto e preco.
8. Se nao houver internet, o app chama carregarDadosOffline.
9. carregarDadosOffline le o SQLite e mostra as imagens salvas.
10. No modo offline, o preco real nao aparece; aparece "a consultar".

FRASE RESUMO PARA APRESENTAR
O app possui dois fluxos. No fluxo online, ele usa um servidor mock HTTP interno para entregar JSON e imagens, le os pratos, baixa as fotos e salva tudo localmente. No fluxo offline, ele le os dados do SQLite, usa as imagens salvas no sistema de arquivos e esconde o preco, exibindo "a consultar".
