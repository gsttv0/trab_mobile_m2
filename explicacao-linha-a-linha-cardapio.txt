EXPLICACAO ORDENADA DO CODIGO - APP CARDAPIO

RESUMO DA LOGICA
O app tem dois modos. Com internet, ele inicia um servidor mock HTTP dentro do proprio app, busca um JSON por HTTP, baixa as imagens desse mock, salva os dados no SQLite e salva as fotos no sistema de arquivos. Sem internet, ele le o SQLite e mostra as fotos salvas. No offline, o preco vira "a consultar".

ARQUIVOS PRINCIPAIS
1. MainActivity.kt: tela principal, fluxo online/offline, leitura JSON, download das imagens e montagem dos cards.
2. MockCardapioServer.kt: servidor HTTP mock interno que entrega o JSON e as imagens.
3. CardapioDBHelper.kt: banco SQLite.
4. activity_main.xml: tela base com ScrollView e LinearLayout.
5. AndroidManifest.xml: permissoes de internet e estado da rede.
6. assets/foto1.jpg a foto4.jpg: imagens usadas pelo mock.

COMO DEMONSTRAR
1. Rodar o app pelo Android Studio com internet ligada.
2. Mostrar que aparecem 4 itens com imagem, nome e preco.
3. Explicar que os dados vieram de um JSON servido por mock HTTP interno.
4. Fechar o app.
5. Desligar internet do emulador.
6. Abrir o app de novo.
7. Mostrar que os dados continuam aparecendo pelo SQLite.
8. Mostrar que o preco virou "a consultar".

FRASE FINAL
Online, o app consome um JSON por HTTP vindo de um mock interno, baixa as imagens e salva tudo localmente. Offline, ele consulta o SQLite e usa as imagens salvas no armazenamento interno, exibindo "a consultar" no lugar do preco.
